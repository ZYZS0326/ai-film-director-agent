# GitHub发布检查表

## 本地工程门槛

- 从干净目录执行 `npm ci`、类型检查、构建和全量测试。
- `npm audit --audit-level=high` 无高危/严重告警，并记录检查日期。
- 桌面包使用隔离项目验证启动、生成、编辑、锁定、恢复与导出。
- 安装包命名包含版本；保留旧包；说明未签名提示。
- 不声称测试证明不存在未知bug，不将模拟模型测试称为真实模型质量验证。

## 源码范围

运行 `node scripts/prepare-source.cjs` 生成独立的 `publish-source/candidate-*` 源码目录。脚本使用白名单排除本地数据，并做有限的密钥特征检查；这不能代替人工审查。只上传该目录的源码，不上传随后安装的依赖或生成的构建产物。

提交 `src/`、`server/`（排除data）、`electron/`、`scripts/`、`.github/`、`docs/`、包清单与锁文件、配置模板和文档。图标仅提交制作所需资源。

不要直接上传整个工作目录。排除 `.env`、用户设置、会话、日志、`.workbuddy-ai`、内部交接文档、缓存、`node_modules`、构建目录与exe文件。检查 `.gitignore`，并在真正提交前人工检查 `git diff --cached`。

## 仍需所有者决策

- 选择公开/私有仓库及名称。
- 选择许可证并确认所有材料的权利归属，之后再添加LICENSE。
- 启用GitHub私密漏洞报告、分支保护；为默认分支要求CI通过。
- 上传后等待Windows/Linux的GitHub Actions实际完成；本地通过不等于云端已通过。
- 需要发行二进制时创建Release并上传安装包，不提交二进制到Git。

本地准备不包含创建远程仓库、推送、公开内容或选择许可证的授权。
